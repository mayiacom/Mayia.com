# Mayia — AI Product Studio

Mayia turns an audience and topic into a tailored digital product concept, five-part content outline, ready-to-edit sales page, suggested price, and five-day launch plan. The drafts are generated by OpenAI through the Responses API.

## Run it locally

1. Install Node.js 20 or newer.
2. Create an OpenAI API key in your OpenAI developer account. API usage may be billed separately from a ChatGPT subscription.
3. In this `app` folder, copy `.env.example` to `.env` and replace `your_api_key_here` with your key.
4. Open a terminal in this `app` folder and run:

   ```sh
   npm start
   ```

5. Open [http://localhost:3210/digital](http://localhost:3210/digital). The root path redirects to `/digital`.

Keep `.env` private. The app ignores it in Git. The local server sends generation requests to OpenAI, so the key is never included in the web page. Change `OPENAI_MODEL` or `PORT` in `.env` if needed.

The app requires internet access and an active API key with API billing enabled. Generated copy is a starting draft; review claims, pricing, and product contents before selling.

## Memberships with Dodo Payments

Mayia creates hosted Dodo checkout sessions for four subscription products. Customers in India can see UPI when Dodo identifies India and INR as eligible; checkout also offers eligible card and Apple Pay methods. The customer enters billing details and authorizes any recurring UPI mandate in Dodo. Dodo handles subscription billing and customer confirmation.

Create four subscription products in Dodo with the same cadence and prices shown on Mayia: $10 weekly, $20 monthly, $50 monthly, and $100 yearly. Copy each product ID. In Dodo, enable Adaptive Currency so Indian subscribers can pay in INR with UPI. Start with Dodo test mode and test product IDs.

In Render's Mayia service environment, set `DODO_PAYMENTS_API_KEY` to the private API key and `DODO_PRODUCT_WEEKLY`, `DODO_PRODUCT_MONTHLY`, `DODO_PRODUCT_STUDIO`, and `DODO_PRODUCT_ANNUAL` to the matching product IDs. Keep `DODO_ENVIRONMENT=test_mode` while testing. For real payments after successful testing and Dodo account verification, switch to `live_mode` and use a live API key and live product IDs. Set `PUBLIC_APP_URL` to the production site origin so Dodo returns customers to Mayia. Never put the API key in browser code or commit it to Git.

Dodo's India subscription flow uses RBI-compliant mandates. Dodo documents a 48-hour pre-debit notification delay for renewals on Indian UPI and cards. Dodo controls the payment and subscription status; Mayia's AI studio remains available during the free beta, and this integration does not yet add Mayia accounts or restrict AI features by membership.

## Website experience updates

The website includes an interactive sample without signup, visitor intent choices that prefill useful starting prompts, an explicitly illustrative before/after example, privacy and AI-limit disclosures, editable sales copy, browser-local projects and recent history, sharing, and plain-text export. Aggregated funnel counts are recorded by day for page views, intent choices, sample starts, generation outcomes, project actions, exports, sharing, and result tabs. No prompt text, IP address, or visitor identifier is recorded. On the local build, see aggregate counts at `http://localhost:3210/api/metrics`.

Browser-local saves do not sync across devices. Mayia does not yet provide account-based membership entitlements or restrict AI features by plan. The generation cap is in-memory and resets when the server restarts or scales; it is a basic abuse guard, not a billing limit. Metrics are also written to the server's local filesystem and can reset on redeploy.

## Deploy on Render and connect mayia.com

The included `render.yaml` is configured for a Git repository whose root is this `outputs` folder. Put the contents of this folder in a GitHub, GitLab, or Bitbucket repository, then in Render choose **New → Blueprint** and connect that repository. Render reads `render.yaml` and creates the Mayia web service. If your repository has an enclosing folder above `outputs`, edit the Blueprint's service Root Directory to `outputs/app` instead of `app`.

In the Render service's **Environment** settings, set:

- `OPENAI_API_KEY`: your OpenAI API key. Add it as a secret in Render; never put it in `index.html` or commit it to Git.
- `METRICS_TOKEN`: a long, random secret. Use it to read `/api/metrics` with an `Authorization: Bearer <token>` header.
- `DODO_PAYMENTS_API_KEY`: Dodo API key stored only in Render. Keep test mode until checkouts work with test products.
- `DODO_PRODUCT_WEEKLY`, `DODO_PRODUCT_MONTHLY`, `DODO_PRODUCT_STUDIO`, `DODO_PRODUCT_ANNUAL`: the four corresponding Dodo subscription product IDs.
- `DODO_ENVIRONMENT`: `test_mode` during testing; change to `live_mode` only with a live Dodo API key and live product IDs.
- `PUBLIC_APP_URL`: the production origin customers should return to after checkout (for example, `https://mayia.com` once the domain is connected).

Deploy and confirm the service health check succeeds. Then open the service's **Settings → Custom Domains**, add `mayia.com` (and optionally `www.mayia.com`), and follow the DNS records Render displays at your domain registrar. DNS targets come from Render's dashboard; do not guess them. Verify the domain in Render. Render provisions HTTPS after DNS verification. The app will be reachable at `https://mayia.com/digital` after the deployment and DNS changes complete; visiting the domain root redirects to `/digital`. Local development remains at `http://localhost:3210/digital`.

Render's free web service may sleep while idle. Its local filesystem is temporary, so the current aggregate analytics file is not durable there. The app's saved projects remain in each visitor's browser. See [Render Web Services](https://render.com/docs/web-services) and [Render Custom Domains](https://render.com/docs/custom-domains).
